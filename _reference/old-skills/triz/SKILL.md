# TRIZ — 40 Inventive Principles

Genrich Altshuller (Soviet engineer/researcher) analyzed 200,000+ patents and found that inventive solutions follow 40 recurring patterns. The core insight: **most problems are contradictions** — improving Parameter A worsens Parameter B. The 40 principles are proven ways to resolve contradictions without compromise.

These principles were born in engineering but apply everywhere. Below, each principle is adapted as a thinking lens for Gordon's actual domains: business strategy, marketing, client work, system design (GordonOS), and personal growth.

---

## How to Use This Skill

1. **Name the contradiction.** What two things seem to be in tension? ("I want X but that means sacrificing Y.")
2. **Scan the principles.** Jarvis presents the groups most likely to apply (not all 40 every time — pick the 2-3 groups that fit, surface 5-8 specific principles).
3. **Apply as lenses.** For each relevant principle, ask: "What would it look like to apply this to my problem?"
4. **Generate options.** Each principle should produce at least one concrete idea. Bad ideas are fine — volume first, filter later.
5. **Evaluate.** Use think-first frameworks (especially real-world trade-offs and inversion) on the best candidates.

## The 40 Principles — Adapted

### Group A: Break It Apart / Restructure

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 1 | **Segmentation** | Divide a monolithic thing into independent parts | Can this service/product/process be broken into modules that work independently? What if each client got a different slice instead of the whole package? |
| 2 | **Extraction** | Separate the useful part from the harmful or irrelevant part | What's the one valuable piece buried inside this bloated process? Can I extract just that and discard the rest? |
| 3 | **Local quality** | Make each part optimized for its specific function instead of one-size-fits-all | Should each client get a tailored version instead of the standard offering? Where is uniformity hurting? |
| 4 | **Asymmetry** | Break symmetry — make things deliberately unequal | What if I gave disproportionate attention to the top 3 clients? What if the system treated mornings differently from afternoons? |
| 5 | **Merging** | Combine similar things to eliminate redundancy | Which of these 5 separate processes are really the same thing? Can two tools become one? Can two meetings merge? |
| 6 | **Universality** | Make one thing serve multiple functions | Can this tool/asset/relationship serve double duty? What if the client report also functioned as a sales tool? |
| 7 | **Nested doll** | Put one thing inside another; use layered/hierarchical structures | Can the solution contain a backup solution inside it? What if the onboarding process contained the retention strategy? |

### Group B: Prepare and Preempt

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 9 | **Preliminary anti-action** | Pre-apply the opposite stress to counteract a known future problem | What's going to go wrong? Can I build the countermeasure in now, before it happens? |
| 10 | **Preliminary action** | Do the hard/slow work in advance so the critical moment is effortless | What can be pre-built, pre-written, pre-decided so that when the moment comes, it's just execution? |
| 11 | **Beforehand cushioning** | Prepare emergency fallbacks before you need them | What's the backup plan? What's the "if this fails" protocol? Build it now, not during the crisis. |

### Group C: Dynamics and Flexibility

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 8 | **Anti-weight / Counterweight** | Compensate for a negative with a deliberate positive | What balances out this weakness? Can I pair a cost with a benefit that makes it net-positive? |
| 15 | **Dynamics** | Make rigid things flexible; allow characteristics to adapt to each stage | What if this wasn't a fixed rule but adapted to the situation? Where would flexibility outperform consistency? |
| 30 | **Flexible shells** | Use lightweight, adaptable wrappers instead of rigid structures | Can the process be a flexible template instead of a rigid procedure? What's the lightest-weight version? |
| 35 | **Parameter changes** | Change the state, form, concentration, or flexibility of something | What if we changed the format entirely? Written → video? Monthly → weekly? Fixed-price → value-based? |
| 36 | **Phase transitions** | Use the effects that happen at transition points | Where are the natural transition moments (new client, new quarter, new hire) and how can we use them as change levers? |

### Group D: Perspective Shifts

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 13 | **The other way round** | Invert the process, relationship, or assumption | What if the client came to us? What if we did the last step first? What if we did the opposite of industry standard? |
| 14 | **Spheroidality / Curvature** | Replace straight-line thinking with curves, cycles, or spirals | What if this isn't linear? What if it's a cycle that feeds back into itself? What does the spiral version look like? |
| 17 | **Another dimension** | Add a new axis — move the problem into a different space | What dimension are we not considering? Time? Audience? Medium? Geography? What if we moved this problem into a completely different context? |
| 22 | **Blessing in disguise** | Use the harmful thing as the solution | What if this problem IS the differentiator? What if the constraint is actually the selling point? |
| 12 | **Equipotentiality** | Remove the need for the effort entirely | Instead of lifting this boulder, can we change the landscape so the boulder doesn't need to move? Can we eliminate the need for this step entirely? |

### Group E: Process Optimization

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 16 | **Partial or excessive action** | If perfection is blocking progress, do 80% or 120% | What if "good enough" ships today instead of "perfect" shipping never? What if we deliberately over-delivered to break through? |
| 18 | **Mechanical vibration** | Use rhythm, oscillation, or resonance | What if we pulsed this instead of running it continuously? What's the natural rhythm this should follow? |
| 19 | **Periodic action** | Replace continuous with periodic; use intervals | What if this wasn't always-on but happened in focused bursts? What's the right cadence? |
| 20 | **Continuity of useful action** | Eliminate idle time; keep the useful work running nonstop | What's sitting idle that could be working? What process stalls between steps? How do we keep momentum? |
| 21 | **Skipping / Rushing through** | Go fast through the dangerous or harmful part | What painful phase can we sprint through instead of enduring slowly? Where does speed itself solve the problem? |

### Group F: Substitution and Replacement

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 24 | **Intermediary** | Use a go-between, broker, or intermediate step | Who or what could sit between us and the problem? Can a tool, person, or process act as a buffer? |
| 25 | **Self-service** | Make the thing serve/maintain/improve itself | Can the client do this part themselves and be happier for it? Can the system monitor and fix itself? |
| 26 | **Copying** | Use a simpler, cheaper copy instead of the original | Can a template, prototype, or simulation replace the real thing for now? What's the $0 version? |
| 27 | **Cheap short-living** | Replace durable/expensive with disposable/cheap | What if this isn't a permanent system but a throwaway prototype? What's the version we're willing to kill in 90 days? |
| 28 | **Replace the mechanism** | Swap the underlying method entirely — use a different type of force | What if we replaced the whole approach? Not a better email — no email at all. Not a better meeting — async instead. |
| 29 | **Pneumatics / Hydraulics** | Use fluid, flowing systems instead of rigid mechanical ones | Can we replace rigid process with something that flows? What's the liquid version of this solid structure? |

### Group G: Feedback and Information

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 23 | **Feedback** | Introduce, improve, or change the feedback loop | Where is feedback missing? Where is it delayed? What if the person/system knew immediately whether it was working? |
| 32 | **Color changes** | Change what's visible; make the invisible visible | What's happening that nobody can see? Can we make the hidden metric, pattern, or problem visible? Dashboard? Signal? |
| 34 | **Discarding and recovering** | Let parts disappear after they've served their purpose; recover what you can | What should be temporary by design? What can we throw away after use and regenerate when needed? |

### Group H: Material and Environment

| # | Principle | Adapted Lens | Example Question |
|---|-----------|-------------|------------------|
| 31 | **Porous materials** | Add porosity — let things flow through instead of blocking | Where are we being too airtight? What if we let information/people/ideas flow through more freely? |
| 33 | **Homogeneity** | Make interacting parts from the same material/culture/system | What if everything in this ecosystem spoke the same language? What if the tools matched the workflow matched the people? |
| 37 | **Thermal expansion** | Use natural growth/contraction forces | What's naturally growing or shrinking? Can we harness that energy instead of fighting it? |
| 38 | **Strong oxidants** | Accelerate a reaction; intensify the active agent | What's the catalyst? What would make this happen 10x faster? What's the concentrated version? |
| 39 | **Inert atmosphere** | Replace the normal environment with a protected one | What's the protected space where this idea can develop without interference? How do we shield this from the noise? |
| 40 | **Composite materials** | Combine different materials/approaches for properties neither has alone | What two unlike things, combined, create something better than either? What's the hybrid approach? |

## The Contradiction Matrix (Simplified)

Altshuller's full system includes a 39x39 matrix mapping improving parameters vs. worsening parameters to the most-likely-useful principles. For Gordon's use:

**Step 1:** Name what you want to improve. (Speed? Cost? Quality? Reach? Simplicity?)
**Step 2:** Name what gets worse when you improve it. (Cost? Complexity? Time? Control? Personalization?)
**Step 3:** Check which principle groups address that specific tension:

| Tension | Start with Groups |
|---------|-------------------|
| Speed vs. Quality | E (Process), B (Prepare), F (Substitution) |
| Cost vs. Capability | F (Substitution), A (Restructure), H (Environment) |
| Scale vs. Personalization | A (Restructure), G (Feedback), C (Dynamics) |
| Control vs. Autonomy | C (Dynamics), G (Feedback), D (Perspective) |
| Simplicity vs. Power | A (Restructure), F (Substitution), D (Perspective) |
| Short-term vs. Long-term | B (Prepare), D (Perspective), E (Process) |
| Innovation vs. Reliability | B (Prepare), C (Dynamics), H (Environment) |

## What This Skill Is NOT

- Not a substitute for think-first — TRIZ is one tool in the toolbox. Think-first decides *whether* to invoke TRIZ.
- Not for every problem — TRIZ shines on **contradictions** (want X but it costs Y). For straight analysis or decision-making, use think-first frameworks directly.
- Not a quick scan — when invoked, expect to spend 10-30 minutes exploring principles. If Gordon needs a fast answer, this isn't the tool.
