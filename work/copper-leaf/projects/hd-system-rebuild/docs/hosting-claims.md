# Hosting research: claims and verdicts (2026-10-01)

Each line: the researcher's claim, its page, then the checker's verdict. "confirmed" means the checker found it at the vendor's own page on the same day.

## Cloudflare

Running this Laravel app on Cloudflare's own compute is poor, and on Workers alone it is not possible without rewriting it. Workers has no native PHP; the only PHP route is a community WebAssembly build that cannot hold a database transaction open, runs one PHP execution per isolate inside a 128 MB limit, and has no place for a queue worker. Cloudflare Containers (generally available since 2026-04-13, Workers Paid plan) will run a normal PHP image, but the disk is ephemeral, so SQLite-on-a-file is out; D1 is reachable from PHP only through hand-written HTTP glue or small community drivers without real transactions; and an always-on queue worker plus every-minute scheduler has to be assembled from a Worker, a Durable Object, a Cron Trigger and keep-alive code. The product was re-architected on 2026-09-30 around agent sandboxes, which is the wrong direction for a ten-year, low-ops business app. The realistic Cloudflare role is the one it already half has: DNS and proxy in front of an origin hosted elsewhere, Tunnel so the origin has no open inbound ports, Access on the admin login (free up to 50 users), and R2 through Laravel's S3 driver for the PDF archive. That middle path costs $0 to a few cents a month on the Free plan, with one rule to respect: free-plan Bot Fight Mode cannot be exempted by WAF rules, so it stays off (or webhooks get carved out another way) so Calendly and mail-provider webhooks are never challenged. So: yes to Cloudflare at the edge of the app, no to Cloudflare as the host; the hosting-shop task is still needed for the origin.

## Laravel's own products

Laravel sells two usable products for this app; Vapor is closed to new signups. Forge Hobby ($12/mo) plus two Laravel VPS 1 GB servers ($6 each) is a flat $24/mo for staging plus production, keeps the SQLite plan (Forge documents SQLite via a shared path), is always on for webhooks, gives root for a later headless Chrome, and carries apps two and three at no extra Forge fee; the maintainer still owns OS-release migrations (new server, move sites), PHP patch clicks, and gets no Forge backups or server monitoring below the $39 Business plan. Laravel Cloud Starter is $5/mo plus usage: about $5/mo if both environments sleep, about $15/mo if production stays awake, with one plan fee covering every later app; but SQLite is not supported, the Cloud docs say Dompdf does not work there, there is no Chrome binary, inbound traffic passes a Cloudflare WAF that cannot be tuned on Starter, and the product's changelog only starts in February 2025 and already shows feature sunsets. Laravel does not name a pick for small apps: its framework docs list Cloud first as the fully managed option and Forge for people who prefer to run their own servers. On the stated constraints (SQLite, DomPDF, later Chrome, ten-year horizon) Forge fits better; Cloud wins only on operations burden and on its scoped API tokens for the staging/production boundary. Laravel VPS region availability in US East was not confirmable from public pages and must be checked before committing.

### What the checker said the report missed

- Kernel reboots on Forge are manual. The report said this was 'not addressed in the docs read'. Forge's own advisory (https://laravel.com/forge/docs/knowledge-base/cve-2026-31431.md) states automatic security updates install the patched package but 'the fix does not take effect until the server is rebooted, and Forge does not reboot servers automatically.' Two servers means two manual reboots per kernel fix.
- Ubuntu LTS lifetime, left as an open question: Canonical's release-cycle page (https://ubuntu.com/about/release-cycle) lists Ubuntu 26.04 LTS standard security maintenance to May 2031 and 24.04 LTS to May 2029. Forge now provisions 26.04 (changelog 2026-08-31).
